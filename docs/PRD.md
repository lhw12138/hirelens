# HireLens PRD v2 · 按招聘任务开展工作

## 可恢复性验收标准

- HR 离开评分页面后，任务仍由后台 Worker 继续执行。
- 超时、RAG 不可用与模型失败必须显示不同原因，并给出恢复动作。
- 首页集中提示失败评分，任务内保留一键重试入口。
- 邮件结果不确定时显示“待核实”，提醒先查发件箱，避免重复发送。
- 系统状态页不得通过主动调用外部模型产生费用，只检查模型配置是否完整。

## 核心用户与目标

HR 已有岗位 JD，需要比较简历、选出面试人选，面试结束后综合全部材料留下可核对的结论。
新用户首次进入应能指出“从哪开始、当前要做什么、做完去哪里”，无需理解 Agent、Skill Pack、RAG。

## 主流程

1. 岗位与筛选标准：创建任务，粘贴 JD。模型整理3–6个默认维度；HR可以编辑、添加或删除，最终3–8项、权重100%。确认后锁定，保持候选人可比。
2. 简历筛选：单份或批量导入简历，逐份核对脱敏文本。模型只读取简历，生成逐项分数、证据与匹配排名。HR主动选择进入面试，系统不自动淘汰。
3. 安排面试与记录：简历中识别到唯一邮箱时自动带出；识别到多个邮箱时要求 HR 选择，未识别到时才手动补充。每位工作台用户配置自己的发信邮箱，填写时间、会议链接或线下面试地址，预览并二次确认后发送面试通知。面试在腾讯会议等外部工具完成；之后上传记录或粘贴文本，检查脱敏并确认。
4. 综合评估：独立的一套默认/自定义维度，生成前可改、首份评估生成后锁定。读取简历与面试两类材料，保存原文引用和冲突。
5. 人工审核：核对分数、原文和缺失信息；填写审核意见以及冲突核实情况；选择进入下一轮、补充信息后再判断、不推进。确认后归档、导出，返回任务继续处理其他人。

第4、5项在用户界面合并为“综合评估与审核”，因此主界面共四步。

## 页面与信息层级

- 首页：新建任务、用示例体验、继续已保存任务；每行显示下一步。
- 任务页：顶部岗位与候选人上下文，四步进度；一次只显示当前任务阶段。
- 筛选页：候选人排名、分数、覆盖项数和进入面试按钮；详细原文折叠展示。
- 记录页：上方安排时间并发送邮件通知，下方上传或粘贴面试记录；邮件和面试资料不进入同一评分上下文。
- 审核页：结论、维度与可展开证据、审核表单；模型版本/Token/耗时在详情。
- 操作记录：实际写入的时间和动作。帮助页解释工作顺序和当前可用范围。
- 旧岗位、候选人、校准等独立入口跳转首页；不重复维护两套用户流程。

## 验收标准

- 默认维度可用，自定义名称、说明、增删、权重均会保存，权重错误不能确认。
- 简历与最终评估标准分别保存，最终修改不影响初筛排名。
- 批量导入失败时不写入半套；导入成功仍需逐份确认脱敏结果。
- 没有初筛评分不能选入面试；没有确认面试记录不能生成综合评估。
- 初筛仅用简历；综合评估工具同时召回简历与面试证据，不跨候选人。
- 初筛评价已检索简历与岗位的匹配度：完整可读的工作/项目经历相关性低时给低匹配分，并说明岗位差距；相关技术或相邻领域经历可获得可迁移匹配分。不能仅因不同行业而机械全部归零。
- 初筛只有材料不可读、关键正文严重缺失、检索内容不足或信息冲突才为null。任一维度为null时暂不计算完整总分，不把未知项折算为0。
- 综合评估仍需简历与面试证据支撑能力判断；不直接套用初筛低匹配逻辑。
- 初筛记录规则版本，排名仅比较新版规则且各维度有分数的结果。旧版初筛在进入面试前可人工触发重评，旧结果保留；已进入后续流程的记录不改写。
- 每次保存都带版本检查；旧版本请求409，不覆盖其他页面更新。
- 模型失败保持已保存数据，显示可重试错误；确认审核需要意见与冲突记录。
- 邮件保存前必须验证 SMTP 登录；发送前必须先生成预览并再次确认收件人、时间和会议地址。
- 邮箱授权码与候选人收件地址加密保存且不写日志；SMTP 超时不自动重试，状态标记为“待核实”，避免重复通知。
- 确认后不能覆盖结果；导出含原始引用、AI分数、人工分数、意见和模型信息。
- 刷新恢复数据库记录，候选人页面没有HR评估或其他候选人的资料。
- 所有示例内容标为合成；不展示未测得的准确率、成本或用户成效。
- 候选人永久删除必须同步清理任务正文、对象存储文件、检索向量、通知地址和访问链接；不能只从页面隐藏。
- 任务先归档再永久删除。归档可恢复，并支持长期保留或归档 30/90 天后清理；永久删除要求输入任务名称确认。
- 管理端不得返回候选人邮箱密文或可使用的邀请令牌；审计记录不得保存被删除候选人的姓名与正文。

## 暂不建设

短信通知、Offer、站内视频面试、候选人在线作答、复杂ATS、企业多租户、OCR、音频转写、微调、自适应追问仍不在本版范围。证据检索已接入本地向量与关键词混合召回、RRF/MMR 排序，尚无人工标注的质量提升结论。
优先让HR从JD走到可核对的完整评估，再根据实际反馈扩大范围。

## 后续路线：候选人自助匹配

登录入口后续区分“招聘方”和“候选人”两种身份。招聘方进入现有招聘决策工作台；候选人进入独立的自助匹配空间，上传一份岗位 JD 与自己的简历，查看逐维度匹配分、证据、差距和可补充信息。候选人数据与招聘方任务严格隔离，匹配结果只服务本人，不自动进入任何企业候选人库，也不得表述为录用概率。

该能力作为后续独立里程碑建设。本版先完成招聘方主流程、评测回归和隐私控制，避免两种角色的信息架构与权限边界混杂。
