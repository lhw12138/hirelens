# 隐私与安全

原始简历先在受控服务内解析，向 HR 展示姓名、电话、邮箱、地址等 PII 的遮盖预览；只有 HR 确认后的片段允许调用外部模型。原文件存储使用私有 Bucket，生产建议启用 OSS 服务端加密、最小权限 RAM 角色和生命周期删除。

日志不得记录原始简历、完整回答、邮箱、手机号或面试会议链接。Trace 保存内部随机 ID、输入摘要指纹、模型/Prompt/Skill Pack/Rubric 版本、工具名、耗时、Token、成本和错误类型。公开仓库只能包含合成数据。

每位工作台用户独立配置自己的 SMTP 邮箱。简历解析时先提取候选人邮箱，再把它从评分文本中遮盖；邮箱仅用于通知。邮箱授权码和候选人收件地址采用服务端认证加密后保存；候选人邮箱仅在当前招聘任务的通知接口中向已登录 HR 返回，普通任务接口不返回明文或密文。发送前展示正文预览并要求人工确认；SMTP 超时或结果不明确时不自动重试，避免候选人收到重复通知。生产环境必须设置并稳定保存 `SETTINGS_ENCRYPTION_KEY`。

## 数据生命周期

- HR 可随时撤销候选人访问链接；撤销后旧链接立即失效。
- 永久删除候选人时，系统在同一受控操作中清理任务正文中的候选人、RAG 向量、面试通知记录，以及对象存储中的脱敏简历和面试记录。操作记录只保留“删除了一位候选人”，不保留姓名和正文。
- 招聘任务首先进入可恢复的归档状态。HR 可以选择长期保留，或设置归档 30/90 天后永久删除；恢复任务会取消自动删除日期。
- 永久删除任务要求输入完整任务名称确认，随后清理数据库任务、级联向量与通知记录，以及 `tasks/<taskId>/` 下的对象存储文件。
- 生产环境应由 SAE 定时任务或等价调度器每日执行 `npm run privacy:cleanup`。清理失败会返回非零状态供监控告警，不会把错误的任务当作已删除。

当前招聘主流程采用“一位候选人对应一份确认稿简历”。因此删除这份简历等价于删除该候选人在当前招聘任务中的完整记录，避免留下没有来源却仍然可见的评分。

普通任务接口不返回候选人邮箱密文，也不返回可使用的访问令牌；管理页面只显示是否仍存在有效链接及其到期时间。
