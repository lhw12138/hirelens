# HR 工作流改版验收

验收日期：2026-09-05。本次只使用显式标记的合成资料，不代表真实招聘质量或业务收益。

## 已交付

- 首页收敛为招聘任务、操作记录与使用帮助，提供示例开始入口与下一步提示。
- 四步主流程：确认岗位要求 → 简历评分排名 → 安排面试并上传记录 → 综合评估与人工审核。
- 新岗位提供可编辑的默认初筛标准；综合评估标准独立保存。确认/评分后锁定相关标准，避免候选人评分口径被静默更改。
- 每项有分数的 AI 判断必须引用当前候选人的确认稿证据。全部证据不足时不展示零分或参与排名；部分不足时明确显示覆盖项数与计算说明。
- 已保存任务与人工审核持久化；刷新保持当前候选人；重复确认与过期版本不能覆盖结果。
- 保留原有数据库表和旧合成素材，新页面使用独立 hiring_tasks 表。旧分散入口重定向，旧生成接口返回410，不再以静态示例结果冒充新流程结果。

## 验证结果

- ESLint、TypeScript 检查及生产构建通过。
- 8个测试文件、19项单元测试通过：包含阶段门槛、标准权重、引用隔离、证据不足、人审完整性和冲突处理。
- 真实模型调用：两份合成简历分别评分；一位候选人导入合成面试记录后生成综合评估，核对两类引用、记录冲突并完成人工确认、导出和刷新恢复。
- 邮件通知：用户配置自己的 SMTP 邮箱；系统先预览、后二次确认发送，并附日历邀请。自动化验收只生成预览，不发送真实邮件。
- 上传接口：文字型PDF、DOCX解析和规则脱敏通过；损坏PDF、空白PDF、非支持格式、超过8MB的文件及未登录上传被拒绝；跨源修改请求被拒绝。
- 桌面1440px、手机390px完成截图检查；主流程无横向溢出。最终截图与运行报告位于Git忽略的 .impeccable/review。
- 按 impeccable 的 distill / polish 流程收敛界面；自动设计检测器缺少随技能分发的执行文件，未能运行，因此不声称自动设计检测通过，已用实际截图核验。

## 重跑

完整流程：设置 HIRELENS_PLAYWRIGHT_PATH 为 Playwright 模块位置，运行 `node --env-file=.env scripts/verify-guided-flow.mjs`。会创建合成任务并产生实际模型用量。

文件验证：设置 HIRELENS_TEST_RUNTIME 为包含 playwright、jszip、pdf-lib 的 node_modules 目录，运行 `node --env-file=.env scripts/verify-document-upload.mjs`。文件在内存生成，不读取真实简历。

发信界面：运行 `node scripts/verify-mail-ui.mjs`。脚本只使用合成候选人与模拟接口，验证桌面/手机布局及预览流程，不连接邮箱、不发送邮件。
