# HireLens · 招聘工作台

围绕一次招聘任务完成：**JD 与筛选标准 → 简历评分排名 → 面试记录 → 综合评估与人工审核**。

首页提供“新建招聘任务”“用示例开始体验”和已保存任务。所有示例显式标记为合成；不宣称真实客户、招聘准确率或人效提升。

## 当前可用功能

- 面向任意岗位，根据输入 JD 生成岗位专属初筛维度和硬性条件建议；HR 可增删、改写、调整权重、修改最低参考线、重新生成或完全自定义，合计 100% 后确认。真实任务不预填产品经理模板。
- 单份或批量导入文字型 PDF/DOCX（每批最多10份、每项任务最多30名候选人），也可粘贴正文。先检查脱敏文本，再用于评分。
- 模型仅读取本候选人的已确认简历证据，输出逐维度筛选评分与原文引用；排名仅辅助阅读，HR 决定是否进入面试。
- 初筛规则 resume-match-v2 区分低匹配、部分/可迁移匹配与材料不足：可读经历不符合岗位时可给低分，不把低匹配一律当作无法评分；真正无法判断的项保留空分，不计完整总分。旧版评分可在进入面试前主动重评并保留历史，新旧规则不混排。
- HR 通过惯用渠道通知候选人。面试后上传 PDF/DOCX/TXT 记录或粘贴文字，确认后保存。
- 每位工作台用户可配置自己的 SMTP 邮箱；候选人邮箱在简历解析时单独提取并加密保存，不进入评分文本。选择时间、填写腾讯会议链接或地址，预览后二次确认发送面试通知，并附日历邀请。服务器接受不等于送达或已读。
- 综合评估有独立可编辑维度，读取简历与面试两类证据；证据不足项给出 0–24 分的低置信度当前材料匹配暂估，并明确标记后计入总分；信息冲突仍交由 HR 核实，不强行评分。
- HR 修改分数、填写审核与冲突记录，选择下一步意见；确认后保留原结果与修改，支持导出 Markdown 底稿。
- 两名以上候选人可进入“候选人对比”：排名先按“硬性条件已满足 / 待核实 / 未满足”分组，再在组内比较加权总分；状态只提示风险，不自动淘汰。页面支持逐维度对比、导出 Markdown 或打印为 PDF，手机端按候选人纵向阅读。
- 数据生命周期：可撤销候选人访问链接、永久删除候选人及其文件/向量/通知记录；任务支持可恢复归档、30/90 天保留策略和二次确认后的永久删除。
- PostgreSQL 持久保存招聘任务与操作记录；版本校验防止并发覆盖。已确认结论不能被重复提交覆盖。
- 页面只展示实际保存与生成的信息，不再展示写死的模型准确率、耗时或人名。

## 本地运行

复制 .env.example 为 .env，配置数据库、对象存储和模型密钥（不可提交 Git）。

```sh
npm install
docker compose up -d postgres minio
npm run db:migrate
npm run dev
```

`npm run dev` 会同时启动网页、本地向量服务和后台评分 Worker，避免任务一直停在“等待后台评分”。如仅调试网页，可使用 `npm run dev:web`；此时评分不会被处理。

MinIO 中需预先创建 .env 的 S3_BUCKET（默认 hirelens）。当前本机已创建。
打开 http://localhost:3000 ，登录后点击“用示例开始体验”，无需真实数据。
本地演示账号 admin@hirelens.local / hirelens-demo。登录绕过开关不再生效。

模型使用 OpenAI-compatible Chat Completions + AI SDK 白名单工具调用。DeepSeek 可设置 MODEL_BASE_URL=https://api.deepseek.com，并配置 MODEL_CONVERSATION / MODEL_REVIEW 和 MODEL_API_KEY。密钥只读服务端环境。

发信邮箱由每个工作台账号在“发信设置”中配置。系统支持 465（SSL/TLS）和 587（STARTTLS），保存前验证 SMTP 登录；邮箱授权码与候选人收件地址使用 AES-256-GCM 加密存储且不写日志。生产环境必须设置稳定的 SETTINGS_ENCRYPTION_KEY，切勿提交邮箱授权码。发送超时会标记“待核实”，不会自动重试，以免候选人收到重复邮件。

## 香港部署

生产部署采用三个独立镜像：SAE Web、SAE 后台 Worker 和私网 RAG 服务，配套香港 RDS PostgreSQL、私有 OSS 与公网 NAT。按 [阿里云香港部署手册](docs/deployment-hongkong.md) 操作；Web、Worker、RAG 的环境变量模板位于 `deploy/`。公网存活检查只返回服务状态，路径为 `/api/live`；包含数据库、队列和模型配置详情的 `/health` 仍需管理员登录。

## 删除与后台评分

任务可删除到“已删除”并恢复，不是永久清除。删除会使在线作答入口失效，未完成的评分不再写回；恢复后需主动重试已取消的评分。

初筛、重评和综合评估先保存到数据库，再由独立后台进程执行。切换或关闭网页不会取消，但电脑、数据库和后台服务需保持运行。评分期间本任务只读，其他任务可正常使用。执行中断的任务在后台重启后超过10分钟会标记失败，可手动重试，不自动重复模型费用。

## 当前实现边界

- 新流程使用 hiring_tasks 表的版本化 JSON 聚合保存单组织小规模任务。旧业务表与历史合成数据保留，不覆盖；旧分散模块入口跳转到主流程。
- 当前使用本地 multilingual-e5-small 向量、pgvector 相似度检索和关键词双路召回，再进行 RRF 融合与 MMR 去重排序。已验证功能链路，尚未通过人工评测证明质量提升；没有接入交叉编码器重排模型。详见 [RAG 设计与运行](docs/RAG.md)。
- 模型评分以确认稿中的段落、字符位置为引用范围，原 PDF 的版面位置不是这一范围。原上传文档只用于解析，确认后的文本存入 MinIO。
- 自动脱敏只覆盖常见规则；用户必须手动检查其他身份信息后确认。称呼不进入评审工具上下文。
- 不提供站内视频面试或候选人在线作答；面试在腾讯会议等外部工具完成。未实现短信通知、ATS对接、扫描件OCR和录音转写。
- 内置30条合成设计标注，覆盖3类岗位和6类风险场景；可在“模型评测”页后台运行并查看引用、冲突与无依据结论指标。它尚未经过真实HR复核，不作为线上准确率。当前没有大规模客户试用数据。

## 面试时如何准确介绍

- 产品取舍：围绕 HR 的筛选—面试—审核工作，主导航缩为招聘任务、操作记录、帮助。
- 模型工具调用：岗位标准与证据均来自服务端限定的当前任务；Zod验证工具参数和输出，引用ID必须属于本候选人。
- 两阶段评估：简历初筛与综合评估分开保存标准；综合评估不能在面试记录确认前运行。
- 记忆：已确认岗位标准、候选人资料和记录按任务及候选人隔离；无跨候选人对话混合。
- 评分：明确答错核心概念或无法完成核心实操属于可判断的负向证据，按依据给低分；只有没问到、没回答或材料缺失才标记证据不足。证据不足项给出 0–24 分低置信度暂估并计入总分，直接冲突留空交给 HR 核实。系统保留 AI 原分、人工修订和原因。
- 暂不微调：先获得可复核的任务样本与人工判断，证明稳定问题后再做实验。
